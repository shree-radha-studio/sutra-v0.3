Sutra CRM · Payments · Log payment sheet — verification
=========================================================

Context
-------
Investigation found that a complete "Log payment" phone sheet (ScreenCrPayLog, body
LogPaymentBody in explorations/catalogue-v2/mod-crm-more.jsx) and its web counterpart
(WebCrPayLog) already existed in the repo, committed as part of the initial CRM build
(commit 068dd5b) and documented in explorations/catalogue-v2/plans/crm.md §2.3 (P7)
and §8. It already covers every element asked for:
  - picks a bill: "Allocate to bills" checklist (Oldest first / Pick bills / On account)
  - amount: "Amount received" field
  - mode: segmented control Cash / UPI / Cheque / bank-transfer (labelled "NEFT", the
    same term already used elsewhere on the board for bank-transfer receipts, e.g.
    mod-crm-more.jsx:250 "05/08/26 · NEFT")
  - a reference number: "Reference" field (UTR ...) plus the paying bank
  - a note: "Note" field
  - confirms: primary footer button "Log ₹39,955"
  - drawn light and dark: automatic via the shared T (FINAL/FINALD) infra
  - already registered on the CRM board page, in the Payments flow, after the bill sheet

The one real gap against the ask ("put it ... after the bill sheet"): the phone
registration order had Snooze between the bill sheet and Log payment
(bill sheet -> snooze -> log payment -> escalate). This also disagreed with the
module's own plan doc, which lists the bill-sheet actions as "Log payment, Snooze,
Escalate" in that order. Fixed by moving the "Payments · log payment" phone
registration to immediately follow "Payments · bill sheet", ahead of snooze, in
explorations/catalogue-v2/mod-crm-phone.jsx (one line, the CRM module registration
IIFE). The web array (which has no separate "bill sheet" frame — bills are shown
inline in the pane) was left as-is; only the phone flow was in scope.
